# Issue tracker: GitHub

Issues live in the repo's GitHub Issues (`gh` CLI). Remote writes are confirmed with the user each time.

- **Publish a story**: `gh issue create` with the story in the body; label `ready-for-refinement`.
- **Fetch**: `gh issue view <n> --comments`.
- **Blocking edges**: native "blocked by" relationship when available; otherwise a `Blocked by` section.
- **Triage**: labels from `triage-labels.md`; comments start with `> *This was generated by AI during triage.*`.

## Wayfinding operations

- **Map**: one issue labelled `wayfinder:map`; **child ticket**: sub-issue labelled `wayfinder:<type>`.
- **Claim**: assign the ticket to the person driving the map, first, before any work.
- **Frontier**: open, unassigned children whose blockers are closed.
- **Resolve**: post the answer as a comment, close the issue, append gist and link to the map's Decisions so far.
